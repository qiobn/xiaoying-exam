# 小影 AI Agent 笔试：企业知识问答 Agent 全局要点

> 本文是后续开发、测试和提交的共同基线，把试卷要求转换为可执行约束。

## 1. 目标与硬性约束

选题为企业知识问答 Agent，目标是帮助员工从合成制度、FAQ 和产品规则中找到可靠答案。核心价值是证据可追溯、冲突可解释、资料不足不猜测。

项目必须提供可复制的 CLI、HTTP API 或 Notebook 入口；本项目优先采用 CLI。必须出现至少一次“模型选择动作 -> 工具执行 -> 观察结果 -> 调整下一步或结束”的循环，并提交至少两条因工具结果不同而产生不同动作的 Trace。必须设置 Agent 步数或工具调用上限，达到上限返回明确未完成状态。真实模型不可用时提供离线 Mock，并明确 Mock 只验证流程。资料全部为合成数据，不提交真实密钥、员工信息或内部制度。

## 2. 必须支持的业务行为

- 根据问题和可选对话历史检索制度或 FAQ。
- 根据结果选择补充检索、读取原文、追问用户或结束。
- 返回答案、文档 ID、版本日期、逐字原文片段、资料缺口和任务状态。
- 识别文档冲突，列出双方证据，说明适用范围或优先级缺口并追问。
- 识别资料外问题，不凭空回答。
- 理解上下文省略和指代，并对当前问题重新检索和引用。
- 工具抛错、超时或空结果时说明影响，不伪造答案。
- 支持近义表达和改写问题。

首版不纳入登录、权限、真实数据、前端、线上部署、多 Agent 和制度自动发布。

## 3. 输入、输出和状态

输入至少包含 question，history 可选。历史只用于补全意图，事实回答仍须由当前工具结果验证。输出固定包含 answer、citations、gaps、status、question_to_user 和 trace。

建议状态枚举：completed（证据一致）、needs_clarification（冲突或缺少前提）、not_found（资料不足）、tool_error（关键工具失败）、step_limit（达到上限仍未完成）。引用必须来自原文读取结果，不能把检索摘要当作证据。

## 4. 工具与动态决策

保留两个核心工具：

1. search_documents(query, top_k)：返回文档 ID、标题、版本日期、范围、摘要和分数；摘要只用于选择下一步。
2. read_document(document_id, query)：返回原文片段、版本日期和适用范围；最终引用必须来自这里。

动作集合为 search_documents、read_document、ask_user、finish。每个 Trace 记录步骤号、动作、参数、返回摘要、后续动作、简短依据和累计调用次数，只记录可审计摘要，不记录模型内部思维过程。默认上限建议为 6 个 Agent 步骤或 4 次工具调用，并用测试验证。

## 5. 冲突规则

若 D01 写明报销期限 30 天、D02 写明 15 天，且没有适用范围和优先级：必须读取并引用两份原文，明确冲突和资料缺口，返回 needs_clarification 并提出具体追问。不得因版本较新、数值更严格或出现更频繁而擅自选一个答案。若用户历史或文档范围明确限定适用人群，可以选择匹配制度，但仍引用范围条款和事实条款。

## 6. 验收矩阵

| 验收点 | 最小场景 | 期望 |
| --- | --- | --- |
| 明确答案 | 单一一致制度 | completed，答案和引用一致 |
| 文档冲突 | 30 天与 15 天无范围 | 双方引用、冲突说明、追问 |
| 资料外 | 未覆盖主题 | 不猜测，not_found |
| 相似改写 | 报销要几天内交 | 命中正确制度 |
| 上下文追问 | 那国外出差呢 | 补全实体后重新检索 |
| 工具失败 | 搜索或读取异常 | tool_error，不伪造答案 |
| 执行上限 | 无法收敛 | step_limit |
| 引用忠实性 | 把 30 改为 45 | 输出随资料改变 |

## 7. 交付目录

README.md、src、tests、data、examples、docs、.env.example 和依赖文件必须位于同一仓库。docs 至少包含 00-project-brief.md、00-exam-overview.md、01-requirements.md、02-solution.md、03-evaluation.md、04-ai-usage.md、05-retrospective.md。examples 至少有正常、资料不足、工具失败三组实际输入、输出和 Trace，评估文档要引用它们。

## 8. 三小时优先级

P0：结构化文档、搜索和读取工具、决策循环、输出契约、上限、离线 Mock、五类核心测试。P1：查询改写、补充检索、版本和范围、冲突检测、引用替换测试、两条不同 Trace。P2：真实模型适配、更多故障注入、日志优化和可选 HTTP 入口。实际用时和未完成项写入评估与复盘文档。

## 9. 提交前检查

- README 可在干净环境复制运行；Mock 与真实模型边界清楚。
- 两条不同路径 Trace、三组验证材料和验收映射齐全。
- 冲突时没有静默选新版本或更严格规则；引用逐字来自原文。
- 触发上限后状态为 step_limit；替换资料后答案和动作改变。
- 不含真实密钥、隐私数据和无关大文件。
- 最终提交题号、GitHub URL 和 commit SHA。
