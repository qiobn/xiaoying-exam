# 复盘

## 1. 关键问题

1. 主 Agent 最初被硬编码为每轮先检索，普通问候也会进入 RAG，并在本地 reranker 联网校验时长时间卡住。
2. DeepSeek thinking 模式的工具消息往返缺少 `reasoning_content`，导致第二次模型调用 400。
3. 本地模型虽然已有缓存，库仍访问 Hugging Face 做模型卡校验。
4. 上下文追问的泛化词会误召回相近制度，例如“国外出差”错误命中“上海报销”。
5. 原前端只能等待最终结果，用户无法看到 Agent 正在检索、读取还是校验。
6. 多轮改写把任何以“怎么样”结尾的独立问题误判为追问，天气问题因此被拼成“今天天气怎么样干什么”。
7. 知识回答触发数值保护时，旧逻辑会直接拼接原始 chunk，导致最终气泡出现“根据知识库原文”和文档版本等元信息。
8. 同一职级在正文和 CSV 中都为 900 时，旧冲突检测按整个 chunk 的数字集合比较，被 P5、上海等无关行误判为冲突。
9. 流式回答曾把每个 token 单独写入 SQLite，一次回答可产生数百条事件，既放大了数据库写入，也让日志面板失去可读性。
10. 图片视觉描述已经生成，但通用问题“这张图是什么内容”和描述没有词法重叠，检索返回空，最终误报资料不足。

## 2. 处理结果

- 改成按需检索，普通交流不绑定工具。
- DeepSeek 兼容端点关闭 thinking；工具链路回归测试通过。
- 本地模型直接解析缓存 snapshot 路径，完全离线加载。
- 增加 query rewrite、新实体覆盖检查和冲突终态。
- 增加 LLM/结构感知分块、表格、图片、大纲重建和视觉理解。
- 增加 SSE token/阶段事件、metrics、幂等键和取消。
- 增加文档删除、重解析、原始文件留存和 20 条检索评测集。
- 将“怎么样”从通用追问后缀改为完整省略句判断，独立天气问题不再改写。
- 增加隐藏操作指南索引、`out_of_scope` 状态和自然语言答案清洗。
- 执行过程与检索溯源改为默认折叠。
- 数值冲突检测改为先按 query 实体选择最相关数字行，再比较对应值。
- token 改为按字符数/时间批量持久化，审计日志只展示阶段、工具、附件和终态；token 与阶段不在原始日志中重复展示。
- 增加图片意图和附件范围检索回退；视觉解析结果明确标记为 `vision`，OCR 不可用不再覆盖视觉成功结果。

## 3. 取舍

- 保留 SQLite 单机架构，没有引入 Milvus、Redis、消息队列和多租户设施。
- LLM 智能分块不是默认处理所有文档；标题清晰、表格文档和短文本走确定性路径，降低成本与风险。
- 对话流式采用协作式取消；正在执行的模型 HTTP 请求不会强行终止，而是在当前调用返回后停止下一步。
- 模型回答在知识类场景先作为 draft 流式显示，引用校验完成后由最终结果替换。

## 4. 已知限制

- PDF 无文本页面仍依赖 Tesseract；复杂扫描件和图表质量取决于外部 OCR/视觉服务。
- 表格拆分保留表头检索上下文，但前端单块正文不重复表头。
- 检索集规模较小，Recall@5/MRR 只能作为回归信号。
- 当前没有生产级鉴权、配额、分布式任务和跨进程 checkpoint。
